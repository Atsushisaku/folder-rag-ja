# 埋め込みとは（具体例つき）

[構造の解説](ARCHITECTURE.md) の「3.4 埋め込み」と「4.1 意味検索」を、実際の数値を使って詳しく説明します。
数値はすべて、このアプリと同じ `bge-m3`（Ollama）で `sample_data/` を実際に計算した結果です（環境によって小数点以下がわずかに変わることがあります）。

---

## 1. 埋め込みとは

**埋め込み（embedding）**は、文章を**数値の並び（ベクトル）**に変換することです。意味の近い文章ほど近い向きのベクトルになるように学習されたモデル（埋め込みモデル）を使います。

たとえば「領収書」という語を `bge-m3` で埋め込むと、1024 個の数値が返ってきます。先頭の 8 個はこうです。

```
[-0.0635, 0.0203, -0.0333, -0.0357, -0.0286, -0.0263, 0.0035, -0.0220, …（全部で 1024 個）]
```

1 つ 1 つの数値に人が読める意味はありません。**1024 次元の空間の中の「向き」**として、文章の意味を表しています。

文字の一致を見るキーワード検索と違い、埋め込みは「レシート」と「領収書」のように**文字が 1 つも重ならない言い換え**でも、意味が近ければ近いと判定できます。これが RAG で埋め込みを使う最大の理由です。

## 2. 近さの測り方：コサイン類似度

2 つのベクトルの**向きがどれだけ揃っているか**を、-1〜1 の数値で表したものが**コサイン類似度**です。1 に近いほど意味が近いことを示します。

このアプリでは、保存するときに全ベクトルの長さを 1 に揃えています（正規化）。こうしておくと、コサイン類似度は**掛け算して足すだけ（内積）**で求まり、全チャンクとの比較も numpy の行列積 1 回で済みます。

## 3. 実例 1：語どうしの近さ

| 語 A | 語 B | 類似度 | 読み取れること |
|---|---|---|---|
| 風邪 | 体調不良 | **0.667** | 言い換えは近い |
| レシート | 領収書 | **0.659** | 文字が 1 つも重ならなくても近い |
| VPN | リモートアクセス | **0.566** | 略語と説明的な言い方も、ある程度近い |
| 領収書 | 会議室 | 0.509 | 無関係でも 0 にはならない |
| 風邪 | 有給休暇 | 0.457 | 関連はあるが、言い換えほどではない |
| SecureLink | VPN クライアント | 0.455 | モデルが知らない製品名は、意味を結び付けにくい |
| 風邪 | プロジェクター | 0.433 | 無関係 |
| レシート | ケイヒくん | 0.359 | 架空のシステム名は、意味を持たない記号に近い |

ここから分かることが 2 つあります。

- **言い換えは高く、無関係は低い**という傾向ははっきり出ます。
- ただし、**無関係でも 0.4〜0.5 程度は出ます**。類似度は絶対的な「関係ある・なし」ではなく、**ほかと比べて高いか低いか**で見るものです（5 章）。

## 4. 実例 2：質問とチャンクの近さ（実際の検索）

質問を埋め込み、sample_data の全 19 チャンクとの類似度を計算して、高い順に並べたものです。これがこのアプリの意味検索そのものです。

**Q：レシートをなくしてしまった**
| 類似度 | チャンク |
|---|---|
| **0.592** | 総務/経費精算.md > **領収書を紛失した場合** ← 正解 |
| 0.469 | 総務/会議室予約.md > 注意事項 |
| 0.429 | システム/障害対応.md > 復旧後 |
| 0.333 | （最下位）VPN接続.md > 初回設定 |

「レシート」「なくした」はどちらも本文に無い語（本文は「領収書」「紛失」）ですが、正解が 2 位に 0.12 の差をつけて 1 位になりました。

**Q：風邪で休むときはどうすればいい？**
| 類似度 | チャンク |
|---|---|
| **0.539** | 総務/休暇申請.md > **年次有給休暇** ← 正解（「急な体調不良の場合は…」を含む） |
| 0.508 | 総務/休暇申請.md > 特別休暇 |
| 0.484 | 総務/休暇申請.md > 半休・時間休 |

上位 3 件がすべて休暇の話です。「風邪」→「休暇」という話題のつながりを捉えています。

## 5. 実例 3：埋め込みの弱点

### 「資料に無い」ことは類似度だけでは判定できない

**Q：社員食堂の営業時間は？**（sample_data には食堂の話は無い）
| 類似度 | チャンク |
|---|---|
| **0.558** | 総務/休暇申請.md > 半休・時間休 |
| 0.474 | 総務/休暇申請.md > 年次有給休暇 |

関係ない質問なのに、1 位は **0.558** です。「営業**時間**」と「午前休は 9:00〜13:00…時間休は…」の「時間」の話題が近いと判断されています。
この値は、正解がある「レシート」の質問の 1 位（0.592）とほとんど変わりません。そのため、「0.55 未満なら資料に無いとみなす」のような**しきい値で切ることはできません**。

このアプリでは、検索はいつも上位 5 件を返し、「資料に無い」の判断は LLM に任せています。指示文の「関係する記述が無いときだけ『資料には見当たりません』と答える」がそれです（[rag_chat/answer.py:14](../rag_chat/answer.py#L14)）。実際、この質問には「資料には見当たりません」と答えました。

### 数字や固有名詞の完全一致には弱い

| 語 A | 語 B | 類似度 |
|---|---|---|
| 1234 | 内線 1234 | 0.803 |
| 1234 | **0123** | **0.593** |

「1234」と「0123」は別の番号ですが、0.593 とかなり近く出ます。埋め込みは「どちらも 4 桁の番号」という**意味の種類**を捉えるので、数字の違いには鈍感です。
型番・内線番号・製品名（「SecureLink」など）のように**文字が一致することに意味がある**検索は、キーワード検索（BM25）の方が得意です。このアプリが 2 つを組み合わせる**ハイブリッド検索**にしているのはこのためです（[ARCHITECTURE.md の 4.3](ARCHITECTURE.md#43-点数の統合)）。

## 6. 実例 4：見出しを付けて埋め込む効果

このアプリは、チャンクを埋め込む前に、先頭へファイル名と見出しを付けています（[`_with_header()`](../rag_chat/index.py#L301)）。

```
新人オンボーディング / 新しく配属された人へ > 初日にやること    ← 付け足す行
- PC を受け取り、初期パスワードを変更する
- 社内チャットに参加し、#全体連絡 と #チーム雑談 に入る
…
```

見出しを付けない場合と付けた場合で、正解のチャンクとの類似度を比べました。

| 質問 | 正解のチャンク | 本文だけ | 見出し付き |
|---|---|---|---|
| 配属された初日にやることは？ | 初日にやること | 0.510 | **0.698**（+0.19） |
| 会議室の定員を知りたい | 会議室一覧 | 0.666 | 0.701（+0.04） |
| 特別休暇の種類 | 特別休暇 | 0.638 | 0.675（+0.04） |
| 経費の支払日はいつ？ | 締め日と支払日 | 0.715 | 0.712（±0） |

- **本文に答えの言葉が無いときほど効きます。** 「初日にやること」の本文は箇条書きだけで、「初日」「配属」という語がありません。見出しを付けると、それらの語で引けるようになり、類似度が大きく上がりました。
- 本文に答えの言葉がそのまま入っているとき（「締め日と支払日」の本文には「振り込まれます」がある）は、ほぼ変わりません。

sample_data は小さいので、どの質問も見出しの有無にかかわらず正解が 1 位でした。資料が増えて似たチャンクが多くなるほど、この差が順位に効いてきます。

## 7. このアプリでの埋め込みの使い方

| 場面 | 何を埋め込むか | コード |
|---|---|---|
| 索引づくり（事前に 1 回） | 全チャンク（見出し付き）。16 件ずつまとめて Ollama に送る | [`_embed_chunks()`](../rag_chat/index.py#L215) |
| 検索（質問のたび） | 質問文 1 つ | [`MultiIndex.search()`](../rag_chat/index.py#L274) |

- 埋め込みは CPU では重い処理なので、**チャンク側は事前に計算して SQLite に保存**しておきます。質問のたびに計算するのは質問文 1 つだけです。
- **索引と質問は、必ず同じモデルで埋め込みます。** モデルが違うとベクトルの空間が別物になり、比べても意味がありません。そのため、設定で `embed_model` を変えると、索引は自動で作り直されます（[rag_chat/index.py:142](../rag_chat/index.py#L142)）。

### bge-m3 を選んだ理由

- **多言語対応**で、日本語の文章を扱える。
- Ollama で `ollama pull bge-m3` するだけで使え、サイズも約 1.2GB と、CPU だけの PC でも扱える。

日本語に特化した埋め込みモデルに替えると精度が上がる可能性はありますが、比較はしていません（未検証）。

## 8. 自分で確かめるには

次のスクリプトで、好きな 2 つの文章の類似度を計算できます（Ollama が起動していること）。

```
uv run python -c "
import numpy as np
from rag_chat.ollama_client import Ollama
a, b = np.array(Ollama('http://127.0.0.1:11434').embed('bge-m3', ['レシート', '領収書']))
print(round(float(a @ b / np.linalg.norm(a) / np.linalg.norm(b)), 3))
"
```

試すと面白い組み合わせ（右は実測値）：

| 語 A | 語 B | 類似度 |
|---|---|---|
| PC | パソコン | 0.802 |
| 締め日 | 締め切り | 0.874 |
| 申請できる | 申請できない | 0.773 |
| 3 万円以上の購入は対象です | 3 万円以上の購入は**対象外**です | **0.897** |
| 申請できる | 会議室を予約する | 0.589 |

最後の 3 行に注目してください。**意味が正反対の文（対象です／対象外です）が 0.897 と非常に高く**、無関係な文（0.589）よりずっと近く出ます。
埋め込みは「何についての文か（話題）」は捉えますが、**肯定か否定かの区別は苦手**です。「対象かどうか」の判断は、検索ではなく、資料を読む LLM が担っています。

検索全体の順位を見るなら、CLI の `--no-llm` が手軽です。

```
uv run python -m rag_chat ask sample_data "レシートをなくした" --no-llm
```
